# 16. Known gaps & limitations

This category collects what each language plugin explicitly does **not** do: gaps admitted in code comments and `gap_for()` rule prose, CHANGELOG "Not covered" follow-ups, unsupported constructs found while cataloguing (section 16 of every `dev_docs/languages/<lang>.md`), and `#[ignore]`d tests. (A grep for `#[ignore` across `crates/` finds none for any language, so that column is left out.) Every per-language doc gives section 16 the scorecard value `n/a`, because it is a list rather than a capability. To compare the lists, this matrix turns them into **recurring gap classes**: shapes of missing support that show up in many languages. Each column is one class. Each cell says how far that language closes the gap. The columns were derived from the union of all 46 section-16 lists. The cross-language claims were spot-checked against code and against fixtures run for this matrix with `target/release/cgg` (scratch: `<scratch>/parity/matrix-16/`).

## Legend

| mark | meaning |
| --- | --- |
| ✅ | full: no gap of this class is known for the language (verified by code or fixture where the column evidence says so; otherwise, no gap was reported in the language doc) |
| 🟡 | partial: supported, with a documented hole or wrong-result case |
| ⬜ | none: the language has the concept, and cgg does not support it |
| — | n/a: the concept does not exist in the language (or in a descriptor/HDL/config language) |
| ? | unverified: the doc is silent, and no fixture was run for this matrix |

A **ᶠ** after a mark means the cell was confirmed by a fixture run for this matrix. Unmarked cells come from the language doc's section 16, or from the code fact cited in the column key.

## Parity gaps

The list is ranked by graph impact: wrong `high` edges first, then missing edges across many languages, then dead-code accuracy, then hygiene. Each item names the languages that lack a capability that a comparable language has. Effort: S = a table row or a small arm, M = a new plugin pass or resolver arm with tests, L = a new inference subsystem.

1. **No parameter/local shadowing table → false `high` edges (13 languages).** Kotlin, Swift, Scala, Dart, Rust, Python, JS/TS, Lua, OCaml and Zig have a `locals.rs` spec. C#, Java, Go, C, C++, Groovy, Solidity, Julia, Haskell, R, Clojure, F#, Nix and Starlark do not (`crates/cgg-lang/src/locals.rs:380-393`). Fixtures `sh/` and `sh2/` show a parameter `helper` binding the same-file function `helper` at **high** in 13 of them (Java cannot call a variable bare, so it is shown 🟡). C# lacks what Kotlin has, Go lacks what Rust and Zig have, and C++ lacks what Rust has. Effort: **M** per language (one `Spec` of grammar node kinds each, plus the shared tests).
2. **Constructor calls do not reach the constructor.** C# (`new T()`, fixture `ctor/A.cs`), Swift (`Foo(...)`, fixture `ctor/A.swift`), Scala (`new Zfoo(1)`/companion `apply`), Ruby (`Foo.new`, fixture `rb/a.rb`), PHP (`new Bar`, fixture `rb/a.php`), Solidity (`new C`, recorded as the name `"new C"`), Groovy (no constructor callables at all, groovy.rs:67-137) and PowerShell (`[T]::new()`) all lack this. Java, Kotlin, C++ and TS bind it (same fixture), and `constructor_names` (cross_file.rs:383-391) handles only Python, JS, TS, PHP and Ruby's `Foo(...)` form. Dart binds the constructor in the same file but not across files (Dart doc §16). Effort: **S** for the C#, Swift and Ruby `constructor_names` and receiver-form rows, **M** for Scala, PHP and Solidity, which need a new call-site shape.
3. **No arity narrowing of overloads.** C#, Kotlin, Groovy, Swift and Solidity lack what Java, Scala and C++ have (`OVERLOAD_ARITY_LANGS`, type_hints.rs:1583). Every overload binds at medium (C# doc §16 #5, Kotlin doc, Groovy #9, Swift #5 where a cross-file lookup keeps only the *last* overload, a wrong edge, and Solidity #12). Haskell hardcodes clause arity 0 (`intra_file.rs:897-900`). Elixir imported bare calls ignore arity (Elixir #1). Erlang falls back to every arity and promotes a single wrong-arity candidate to high (Erlang #4). Effort: **M** (each plugin must set `RefRecord::arity`, and its parameter-list parser must accept defaults and varargs).
4. **Untyped locals, fields and return types.** TypeScript and JavaScript write no `local_types`/`class_fields` at all (TS doc #1, JS doc). Java and C# have no return types (`type_hints.rs:2632-2672` handles only `->`, `): T` and Go) and no field types. All of these lack what Rust and Kotlin have (lets, fields and returns, per CLAUDE.md Phase 3). Dart, Swift, Groovy, Lua, Ruby, PHP, Perl, Objective-C and Elixir type parameters at most. Effort: **L** for TS/JS (the dominant source of medium fan-out), **M** each for Java/C# return types and fields.
5. **Function values passed to ordinary calls are not references.** JS, TS, Go, Kotlin (`::f`), Swift, Scala, C, Ruby (`method(:x)`), PHP (string callables), Lua and Starlark lack what Java (method refs), C# (method groups), Python, Rust and Elixir (`&f/0`) have (fixture `vr/`, `--reference-edges`). Go declares `value_refs: true` (go.rs:44) and still does not link `apply(target)`. The result is false dead-code findings. Effort: **M** per language.
6. **Module-qualified calls never bind.** Perl `Pkg::f()` (Perl #1), Haskell `M.f` (haskell.rs:208-210), OCaml `Mod.f` (ocaml.rs:127-137 module QN bug), Julia `Mod.f()`, F# `A.B.f` (silently dropped), R `pkg::f` (by bare name, high) and Swift `Module.f()` all lack this. Elixir (`LibIndex::resolve_elixir`), Erlang `m:f`, Clojure `alias/f` and Go packages have it. Effort: **M** each. OCaml's QN bug is **S**.
7. **No external-module refusal.** Swift, Groovy, Ruby, Perl, R, Julia, Haskell, OCaml, F#, Solidity, PowerShell, Starlark and Objective-C name-match external calls into the workspace. Python, JS/TS, Go, Java, Kotlin, C#, Scala, C++ (`heads.rs:413-630`) and Rust refuse them. Groovy produced a wrong medium edge to an unrelated method (Groovy #6). Effort: **M** (each needs an import-table arm and a `WorkspaceVocab` source such as `FileFacts::packages`).
8. **No visibility signal → dead code capped at `medium`.** TS, JS, PHP, Ruby, Swift, Scala, Dart, C, C++, Elixir (`defp`), Erlang (`-export`), Haskell (export lists), Zig (`pub`), OCaml, F#, Clojure (`defn-`), Lean, Julia (`export`) and Fortran lack what Java, Kotlin, C#, Go, Python, Rust and Solidity have (`PluginSignals.visibility`). Effort: **S** for Elixir `defp`, Zig `pub`, Erlang `-export`, Clojure `defn-` and Haskell exports (all explicit syntax). **M** for C/C++ `static`/anonymous namespace and TS/JS `export`.
9. **No `override` marker → no `implements-external-contract` cap.** `OVERRIDE_MARKERS` reads `@Override`, `override` and `@override` (deadcode/mod.rs:409). Only Java annotations and C# (`csharp.rs:337-342`) record one. Kotlin (kotlin.rs mentions `override` only in tests), Swift, Scala, TypeScript and Dart (whose attributes are only `"abstract"`, dart.rs:119) have the keyword but do not record it. Python reaches the cap by a different path, but async methods escape it (python.rs:522, deadcode/mod.rs:505). Effort: **S** each.
10. **No enumerating test harness.** JS/TS (jest, vitest and playwright are all `(gap)`), C++ (gtest), Scala (scalatest, specs2), Elixir (no ExUnit rule), Dart (flutter-test), Groovy (spock), Zig (test blocks are not callables), OCaml, Perl, R, Julia, PowerShell and Clojure lack what Java (junit/testng), Python (pytest), Rust (cargo-test), Go, PHP (phpunit) and C# (xunit/mstest) have. Kotlin lacks Kotest/Spek. Effort: **M** each; JS/TS first (largest corpus share).
11. **Inheritance and dispatch.** Objective-C (no bases, so `super` fans out to unrelated classes), Solidity (no base-contract records), PowerShell, F#, Lean, Perl (not in `INHERITANCE_LANGS`, though `@ISA` is walked) and Fortran (OO) lack what the twelve `INHERITANCE_LANGS` have (dispatch.rs:110-123). Go has no interface→impl dispatch even with `--dynamic-dispatch`, which Rust has through trait `fanout` (Go #5). Swift, PHP and Ruby lose the bases of classes with no methods (Swift #9, PHP #10, Ruby #7). Effort: **M**.
12. **Top-level and script code has no enclosing callable.** PowerShell, Nix, OCaml (`let () =`), C# (top-level statements and field initializers), Groovy and Gradle scripts, Kotlin `.kts`, Swift top level, Starlark BUILD and F# `.fsx` give `no-enclosing-callable`. Python and Bash root top-level invocations (`toplevel:invocation`), as do Lua and Elixir, though too broadly (Lua #7, Elixir #7). Effort: **M** (a synthetic per-file callable, or a root).
13. **Lambdas, closures and blocks are not callables** in C++, Kotlin, Swift, Scala, Groovy, Lua, Ruby (blocks, `define_method`), PHP, Perl, Julia, Haskell, OCaml, F#, Clojure, Nix, Lean, Starlark, Dart and PowerShell. Rust (spawned closures), JS (registrar handlers) and Python (named lambdas) cover them in part. Effort: **M–L**.
14. **Fixed descriptor cap of 4 ignores `--fanout-cap`** for smithy, proto, graphql, openapi and asyncapi (`cross_file.rs:5228-5240`). Every code language honours the flag. Effort: **S**.
15. **Descriptor → implementation link.** OpenAPI and AsyncAPI are excluded from `DESCRIPTOR_LANGUAGES` (descriptor.rs:47). GraphQL is included but structurally dead, because fields are not nodes (GraphQL doc §16). Proto and Smithy have links that work in part. Effort: **M**.
16. **Case-insensitive languages are matched case-sensitively.** Fortran, VHDL, CMake, PowerShell, and PHP function names (where the stdlib lookup is case-sensitive too) are affected. No language has case folding. Effort: **S–M** (normalise the simple-name index per language).
17. **Conditional and preprocessor alternatives.** C# re-parses with `#if` blanked (csharp.rs:69,683), and PHP marks `DefRecord::conditional`. C/C++ extract `#if 0` and bind one alternative at high cross-file (fixture `cpp/`; CHANGELOG.md:176-178 covers only in-header alternatives). Swift, F# and Fortran extract every `#if` branch. Haskell loses CPP `#else` arms. Python, Bash, R, Clojure and Lua redefinitions bind every copy. Effort: **M**.
18. **Reflection screens.** The `REFLECTIVE` table (dynuse.rs:24-53) covers only Python, Ruby, Java, C#, JS, TS, PHP and Go. Kotlin, Scala, Swift (`#selector`), Objective-C (`performSelector`), Elixir (`apply/3`), Erlang (`apply`/MFA), Clojure (`resolve`), Lua (`loadstring`), Perl, C (`dlsym`) and PowerShell lack it. Effort: **S** each (table rows).
19. **Language families disabled.** JVM (Java/Kotlin/Scala/Groovy), JS/TS and C#/F# sibling lookups are commented out (`crates/cgg-core/src/lang_family.rs:29-34`). Only c/cpp/objc is a family. Mixed Kotlin+Java and `.ts`+`.js` trees therefore lose cross-language bare calls (Java #13, Kotlin, TS #12). Effort: **M** (the comment requires tests first).
20. **Missing stdlib tables.** PowerShell, Solidity, F#, Starlark, CMake, Nix, Lean, Verilog and VHDL have none (no `crates/cgg-core/src/stdlib/<lang>.txt`), so builtins fill the external bucket and `--include-stdlib` yields nothing. Comparable scripting and functional languages (Bash, OCaml, Haskell) have tables. Effort: **S** each.
21. **Detection and routing.** The Bash `sh` substring needle claims pwsh, perl (`/home/shared/...`) and fish shebangs (Bash #2, PowerShell #1, Perl #9). `ts-node` routes to JS (TS #8). Dart `bin/` and Perl `bin/` are denied (`cgg-walk/src/lib.rs:57`). CMake `CMakeLists.txt`, Starlark `BUILD`, Ruby `Gemfile`/`Rakefile` and Groovy `Jenkinsfile` are not detected. Objective-C headers are parsed as C. Effort: **S** each.
22. **Unreachable regions are computed and never consumed (all 8 producers).** Rust, Python, JS, TS, Go, Java, C and C++ write `FileFacts::unreachable` (e.g. `rust.rs:120`, `python.rs:119`, `cfg.rs:184-232`). No crate outside `cgg-lang` reads the regions: `crates/cgg/src/lib.rs:1935` copies only the boolean signal. A call after `return` therefore keeps its target live, and in TS stays `high` (TS #6). Effort: **S** (drop or flag sites in regions before Phase 3).
23. **In-file test role.** Only Go, Python and Rust set `DefRecord::test_role` (grep `test_role` in plugins). Rust's `#[cfg(test)]` module helpers get none (`rust.rs:3115` asserts None), although a comment claims an in-file signal (`crates/cgg-core/src/testfile.rs:69-71`). Effort: **S**.
24. **Parse-error fallback.** Only C# re-parses. Groovy (weak grammar), CMake, HCL, Erlang, Fortran (fixed form), Proto (`group`), Smithy, GraphQL, PowerShell and Verilog/SystemVerilog lose definitions after an error with no fallback. Effort: **M** (grammar-specific).

## Doc corrections

- **CLAUDE.md, dynuse coverage**: it says `dynuse` "covers Python, JS, Java, C#, Ruby and PHP". `REFLECTIVE` also lists `("typescript", &["require"])` and `("go", &["MethodByName", "FieldByName"])` (`crates/cgg-lang/src/plugins/dynuse.rs:46-51`). The go, typescript, javascript and php plugins also write `dyn_uses` (`grep -ln dyn_uses crates/cgg-lang/src/plugins/*.rs`). The language docs for Go and TS are consistent with the code; CLAUDE.md is the stale one.
- **CLAUDE.md, arity → `high`**: it says `high` covers "an overload set narrowed to one by arity". That holds only intra-file. Fixture `ar/` gives `p.Same.run -> p.Same.g high intra-file`, but `p.Main.run -> p.Lib.f medium cross-file:imports` for both arities. The Java doc §16 #10 is correct.
- **Rust doc §16 and Java doc §16 omit the unreachable-region gap** that the Python, JS, TS, C and C++ docs state. `rust.rs:120` and `java.rs:53` write `FileFacts::unreachable` with no consumer anywhere (grep `UnreachableRegion\|\.unreachable\b` outside `cgg-lang/src/plugins` finds only the struct definition, `cgg-core/src/facts.rs:204,533`, and the boolean at `cgg/src/lib.rs:1935`). The Rust note "CFG unreachable ignores diverging macros" implies the regions matter. They do not affect output today.
- **Rust doc path precision**: "testfile.rs:69-71" is `crates/cgg-core/src/testfile.rs:69-71` (the claim itself is correct: the comment promises an in-file `#[cfg(test)]` signal, and `rust_test_role` returns None for it, rust.rs:3115).
- **Kotlin doc, addition**: the grammar gap is wider than "a one-line nested class body". A top-level one-line class with members (`class Kfoo(val x: Int) { init { } constructor(a: String) : this(1) { } fun m() {} }`, fixture `ctor/A.kt`) extracted a single callable named `m` with kind `constructor`, and `Kfoo.m` was lost. The same class written across lines extracts `Kfoo` (constructor) and `Kfoo.m` correctly (fixture `kt/`). Also, secondary constructors and `init {}` blocks are not separate callables: both `Kfoo("a")` and `Kfoo(2)` land on the single `Kfoo` node.
- **Dart doc, addition**: a same-file construction does bind (`drun -> Dfoo::Dfoo high intra-file`, fixture `ctor/a.dart`), but the constructor node has kind `method`, not `constructor`. Constructor-kind consumers (dead-code constructor roots, `--why-live`) therefore treat it as a plain method.
- **Swift, Scala, Dart and Python observation (not an error in the docs)**: a same-file typed-receiver call such as `f.m()` after `let f = Sfoo(...)` was bound by `cross-file:imports` at `medium`, not intra-file at high (fixtures `ctor/`, `rb/a.ts`). The Swift doc's "no local typing" (#3) explains Swift and Scala. For TS this matches TS doc #1.
- **C doc §16 #3** is confirmed for the `.c`-alternatives shape (fixture `cpp/`: `main -> dbg high cross-file:imports` with two `#ifdef` bodies in `lib.c`). The CHANGELOG.md:176-178 fix covers alternatives inside the include closure only, so the two are not in contradiction. The C doc's phrase "contrary to CHANGELOG" overstates it.
- **Haskell doc §16 #15** says "No QuickCheck or HUnit rule exists". That is true, but the doc should also say that `tasty` and `hspec` *are* enumerating test rules (rules.rs `TrustKind::Test`, tabulated above). Otherwise a reader concludes that Haskell has no test harness.
- No doc claim checked in this pass was found to be contradicted by code, other than the CLAUDE.md items above. Cells marked `?` were not verified.
