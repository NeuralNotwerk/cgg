# 05. Type inference & receiver typing

**Definition.** *Type inference & receiver typing* is everything cgg does to replace a call site's receiver text (`s` in `s.run()`) with the type that receiver holds, so that the typed-owner lookup (`(language, owner type, method)` in `cross_file.rs`) can bind the call to one class's method instead of fanning it out by name. Typing information comes from three places:

- **Plugin-recorded facts:** `FileFacts::local_types`, `field_types`, `class_fields`, `type_aliases`, `scoped_types`, `type_spans`, `closure_args`, and `RefRecord::typed_receiver` / `implicit_receiver` / `arg_type`.
- **Signature text** (`signature_hint`), parsed by `type_hints::collect_param_types` and `extract_return_type`.
- **Resolver-side heuristics:** Strategy 2 (a receiver spelled like a lower-cased type the file declares) and Strategy 4 (a receiver spelled like a known return type). `RefRecord::weak_receiver_type` exists to mark these guesses.

All of it runs in `type_hints::propagate_types_with_fields` (`crates/cgg-resolve/src/type_hints.rs:379-945`), plus the settle passes `settle_assoc_call_locals` (:1037), `settle_closure_args` (:1115), `settle_implicit_receivers` (:1379) and `settle_unwrapped_bindings` (:1847). Inheritance walks, overloads and `super` belong to §06. Shadowing by locals that carry no type belongs to §07. How confident a typed edge is belongs to §14. The **Guard** column below is the one exception: it records whether a *guessed* type can produce a `high` edge, because that is a property of how the typing pass marks its own output.

Sources: section 05 and scorecard row 05 of all 46 `dev_docs/languages/<lang>.md`. The matrix was then spot-checked against the code and against fixtures run with `target/release/cgg` 0.11.0 under `<scratch>/parity/matrix-05/` (listed at the end). Where a language doc and the code or a fixture disagree, the matrix follows the code or fixture; see **Doc corrections**.

## Legend

| mark | meaning |
| --- | --- |
| ✅ | full: the capability works for the language's ordinary spellings of the concept |
| 🟡 | partial: only some spellings, only at reduced confidence, or only through a heuristic |
| ⬜ | none: the language has the concept, but cgg types nothing from it |
| — | n/a: the concept does not exist in the language, or the language records no receivers at all, so there is nothing to type |
| ❔ | unverified: no doc covers it and no fixture was run, so it is left ungraded |

## Parity gaps

Ranked by how many languages share the gap and how much of the graph it touches. Effort: S = a table row or a few lines in one function, M = a new plugin pass or one resolver branch, L = new modelling.

1. **A guessed receiver type binds `high` whenever the candidate is in the same file, in 19 languages.** Strategy 2 (type_hints.rs:863-866) types any receiver spelled like a lower-cased type the *file* declares, and marks it `weak`. `cross_file.rs:2724` honours the mark, but `intra_file.rs` never reads it: a single same-file candidate is always `Confidence::High` (intra_file.rs:633-638). In each fixture `service = mk()` returns an int (or `Object`/`Any`), yet `service.run()` bound `Service.run` **high**, while the same code with `zzz` fanned out or stayed unresolved. Affected: rust, python, javascript, typescript, go, java, kotlin, cpp, csharp, ruby, swift, lua, dart, scala, objc, groovy, solidity, fsharp, lean (fixtures `heur/`, `heur2/`, `heur4/`, `heur5/`). Unaffected: zig, which skips the heuristics (type_hints.rs:819-821); erlang, which is exempt (:389); and php, perl and powershell, whose `$` receivers never match. The cross-file version stays out of `high` (fixture `heur3/`: unresolved). Fix: carry `weak_receiver_type` into `intra_file` confidence. **S**.
2. **Java, C#, Dart, Groovy, C, C++ and ObjC never read a declared return type**, while Kotlin, TypeScript, Swift, PHP, Scala, Rust and Go do. `extract_return_type` (type_hints.rs:2632-2671) only parses `->`, `):` and `) T`. Its comment at :2650 claims Java/C#, but no branch does it. As a result `var t = makeTool(); t.work()`, `getTool().work()` and `Foo.Make().M()` fan out or stay unresolved (java.md §05 fixture f4, csharp.md §05 fixtures f1 and f8), and the Strategy 4 name match never fires for these languages. Fix: a type-before-name reader (`[modifiers] Type name(`), sharing `parse_type_first_param`'s modifier list. **M**.
3. **Go method receivers and same-package parameters are untyped**, although package-qualified parameters are typed (`go_package_param_types`, type_hints.rs:1496-1530). In `func (s *Server) Zap() { s.zip() }`, `s` gets no type; the generic type-first parser reads `q *Server` back to front and rejects it (type_hints.rs:2181, 2200). Go is name-first, like Kotlin's `name: Type`, which is typed. Evidence: go.md §05 fixtures f1 and f4; CHANGELOG.md:1479-1480. **S**.
4. **Field/property typing exists for Rust, Python and C++ only.** Java, C#, TypeScript, Swift, Dart, Go, PHP, Groovy, Solidity, Ruby (`@ivar`), ObjC and Lua have the concept but record nothing. Kotlin types declared properties but not primary-constructor properties (CHANGELOG.md:709). Scala and Kivy write `class_fields`, but type propagation never reads them: the only readers are ffi.rs:279-296 (Kivy), heads.rs:128 and frameworks/mod.rs:1711, and fixture `heur/scala` shows `svc.area()` and `helper.area()` fanning out to both owners. Fix: emit per-class `self.`/`this.` local types the way Python's `emit_instance_field_types` does, or teach propagation to read `class_fields`. **M** per language (Scala and Kotlin constructor properties are **S**, since the data is already recorded).
5. **Explicitly typed locals are typed in Rust, Java, C#, Kotlin, C++, Zig and Go only.** TypeScript (`const s: Service`), Swift (`let e: Engine`), Dart (`Foo typed`), Scala (`val c: Square`, fixture heur/scala), Groovy (`Foo x`, fixture narrow/groovy), Python (`sq: Square = …`), Solidity, F#, PowerShell (`[T]$s`), ObjC (`Engine *eng`), Lean and Julia write no `local_types`. The grep that lists the `local_types` writers is under **LDecl** in the column table. **M** per plugin (the resolver side already exists).
6. **Constructed locals** (`x = Foo()`) are typed in Python, Java, C#, Kotlin, Rust and Zig, but not in JavaScript/TypeScript (`const x = new Foo()`), Ruby (`Dog.new`), Swift, Dart, Scala, PHP, Lua (`Animal.new()`), Perl (`Pkg->new`), Groovy, Solidity, F#, PowerShell (`[T]::new()`), R or C++ `auto`. The receiver-position form is already typed for most of them (column **Cast**), so the plugin only needs to record the assignment. Evidence: javascript.md fixtures f2/f5, ruby.md fixture p2, php.md fixture p1, cpp.md fixture f4 L18. **S–M**.
7. **Closure parameter typing is Dart, C# and Scala only** (closure_types.rs:25-68, called from those three plugins). Kotlin lambda parameters and `it` (kotlin.md fixture f10), TypeScript inline arrows (typescript.md fixture f16), Swift closures (swift.md fixture f4 L49-50), Java lambdas, Groovy typed closures (fixture narrow/groovy) and Rust `|x: T|` are untyped. `CALLBACK_TYPE_CONSTRUCTORS` (stdlib.rs:141-147) has no row for Kotlin `(Foo) -> Unit`, TS `(x: Foo) => void`, Java `Consumer<Foo>`/`Function<Foo,R>`, Swift `(Foo) -> Void` or Python `Callable[[Foo], R]`. **M** (the settle pass is generic; each language needs a `closure_types.rs` arm plus a table row).
8. **Flow and pattern narrowing exists only for Rust (`if let`/`match`) and Scala (`case d: Dog`).** Kotlin smart casts (kotlin.md fixture f7 L13), Java/C# patterns (`o is Svc pat`, csharp.md fixture f1), Dart `is` (fixture narrow/dart), TypeScript `instanceof` (fixture narrow/ts), PHP `instanceof` (fixture narrow/php), Go type switches, Swift `if let`/`guard let` (swift.md fixture f4 L41) and Python `isinstance` are untyped. Typed iteration variables are also untyped everywhere: Java enhanced-for, C# `foreach (Svc each …)`, Dart `for (Foo it in …)` and C++ range-for. Those are declared types, so they are **S** for languages that already record locals. **M–L** overall.
9. **Locals are file-wide, last write wins, in Java and Python**, while C#/Kotlin look in the calling function first (type_hints.rs:785-801), and Rust, Zig and C++ look up the binding in scope. java.md fixture f5 bound `one()`'s `x.go()` to `B.go`. Out-of-scope readings are marked weak (type_hints.rs:805-811), so the damage is a wrong medium edge cross-file and possibly a wrong `high` intra-file (gap 1). Adding `"java"` to the C#/Kotlin branch is **S**. The type_hints.rs:719-735 comment records that scoping *every* language at once lost 1,698 high edges, so measure per language.
10. **Generic-bound receivers are Rust-only (and only for single-bound struct fields).** `fn f<T: Shape>(t: &T)` (rust.md fixture), `function g<T extends Service>(t: T)` (typescript.md fixture f16), Java `<T extends Svc>`, C++ CRTP (cpp.md fixture f5 L18), Kotlin `T : Svc` and Swift `T: Proto` are unresolved. A grep for bound handling finds only rust.rs. **M**.
11. **Type aliases are followed only in C++, Rust and Zig.** `type_alias_index` skips every other language (type_hints.rs:121), and only cpp.rs writes `type_aliases`. Swift `typealias W = Widget` gives an unresolved call (swift.md fixture f8 L28). TS `type A = B`, Kotlin `typealias`, Go `type A = B`, C# `using A = B;`, Dart `typedef`, F# abbreviations, ObjC/C `typedef` and Lean `abbrev` are not followed. **S** per plugin (push `TypeAlias` and drop the cpp-only filter).
12. **Casts and constructions in receiver position are missing for Solidity (`IVault(addr).f()`, `new C().f()`), PowerShell (`[T]::new()`, `[T]$x`), F# (`:>`/`:?>`), Groovy `as` (receiver lost, fixture heur/groovy), Zig `@as`/`@ptrCast`, ObjC `(A *)o`, Python `typing.cast` and Rust `as`.** Java, C#, Kotlin, Swift, Scala, Dart and C++ have them. Each is a `receiver::peel` arm or a `CAST_INTRINSICS` row (stdlib.rs:34-45). **S** each.
13. **Wrapper see-through is Rust-only (plus C++ `->` pointee).** C# `(await t).M()` with `Task<Foo> t` reads `Task` (csharp.md fixture f8 L17; CHANGELOG.md:1474-1476), and Kotlin `val g by lazy { Svc() }` is untyped (kotlin.md fixture f7 H6). The same applies, by grep, to TS `await Promise<Foo>` and Dart `await Future<Foo>`: no such table exists outside `rust_types.rs`. A per-language "await unwraps" row next to `MAYBE_TYPE_WRAPPERS` would cover them. **S**.
14. **Implicit/context receivers are Kotlin-only** (`settle_implicit_receivers` filters on `f.language == "kotlin"`, type_hints.rs:1388). Groovy `with {}`/`tap {}`/closure delegates (cross_file.rs:4084 comment), Ruby `instance_eval`/`instance_exec` DSL blocks and Scala implicit classes (scala.md fixture f2: `3.double` bound nothing; CHANGELOG.md:1491-1493 counts 741 corpus sites) are untyped. **M**.
15. **`self` is not typed to its table in Lua** (lua.md fixture p1 L16: `ambiguous-in-file`). PowerShell `$this` is untyped (powershell.md fixture f11: `$this.Hello()` fans out to an unrelated class). Python, Ruby, Swift, ObjC, F# and Perl (invocant) bind `self`/`this` to the caller's type. **S–M**.
16. **The run-wide return-type map is keyed by bare function name across all languages, and the first definition wins** (`build_return_type_map`, type_hints.rs:272-287: `map.entry(def.simple_name).or_insert(ret)`, with no language in the key). Two `make()` functions with different return types, or a same-named function in another language, give whichever was seen first. This affects every Strategy 4 user (Python, TypeScript, Kotlin, Swift, Scala, Go, Rust). Found by code reading; no fixture run. **S**.
17. **`TOP_TYPES` only gates closure settling** (its sole reader is `concrete_class`, type_hints.rs:1363). A parameter typed `Object`/`Any`/`dynamic`/`AnyObject`/`any`/`unknown` is still rewritten to that type and then refused or booked as stdlib. Examples: Dart `void f(Object p)` gives `candidates-in-other-files` with receiver `Object` (fixture narrow/dart), Swift `AnyObject` gives `<stdlib>::AnyObject::go` (swift.md fixture f5), and Java `Object service` gives receiver `Object` with 2 candidates (first `heur/java` run). The table also has no rows for Kotlin, TypeScript, Swift, Java or Groovy. **S**.
18. **PHP types parameters but no locals and no properties.** `$y = new Helper(); $y->help()` goes external (php.md fixture p1 L38), while Python and Java type the same shape. Docblock `@var`/`@param` are not read (fixture narrow/php). **M**.
19. **Lean applied types are kept whole** (`List Nat` never matches `List`; lean.md fixtures iso/gen g1-g3), and `declared_type` only strips `?`/`!`/`|`/subscripted wrappers (annotation.rs:30-68). Peeling the head of a juxtaposition type is **S**.
20. **ObjC types nothing from its declarations**, even though `(A *)param` and `Engine *eng` are as explicit as the C++ pointer parameters that cpp.rs types (objc.md fixtures f2 and f3). **M**.
21. **Julia argument-type dispatch is not modelled.** `area(c)` with `c = Circle(1.0)` binds all three `area` methods (julia.md fixture p1), and `RefRecord::arg_type`, which Rust uses for trait-impl narrowing, is unused. **L**.

## Doc corrections

1. **scala.md §05, "Locals" and "Fields and constructor parameters":** wrong. The doc says `val s = new Square(2.0)` and `val c: Cat = new Cat` "are typed by the generic file-wide propagation", and that `class_fields` types `svc`/`helper`. In fact the Scala plugin writes no `local_types` (grep: the writers are csharp, java, kotlin, c_macro, go, rust, cpp, python and zig), and type propagation never reads `class_fields` (its readers are ffi.rs:279-296, heads.rs:128 and frameworks/mod.rs:1711). In fixture `heur/scala`, `svc.area()`, `helper.area()`, `val s = new Square(); s.area()` and `val c: Square = mk(); c.area()` each fanned out to **both** `Square::area` and `Circle::area` at medium. The medium edges in the doc's fixtures are by-name fan-out that happened to have one candidate. The scorecard phrase "local/field typing only medium" should read "local/field typing: none".
2. **lean.md §05, "File-wide locals, last write wins (false `high`)":** wrong cause. The Lean plugin writes no `local_types`. The false high comes from Strategy 2, the lower-cased-type-name heuristic (type_hints.rs:863-866), combined with intra-file ignoring `weak_receiver_type`. In fixture `heur/lean`, `def useU := fun p => p.go` bound `P.go` **high** (`p` is `P` lower-cased), while the identical `def useV := fun zz => zz.go` fanned out to `P.go` and `Q.go` at medium.
3. **lua.md §05 ("None for Lua"), ruby.md §05 ("Local variable typing" not supported), and every doc that omits it (rust, go, java, kotlin, cpp, csharp, scala, groovy, solidity, fsharp, dart):** the generic Strategy 2 heuristic does apply to them. It types any receiver spelled like a type the same file declares, and the result binds **high** intra-file even when the value is unrelated. Fixtures: lua `service:run()` gave `Service:run` high; ruby `service.run` gave `Service::run` high; go, java, kotlin, csharp, rust, cpp, scala, groovy, solidity, fsharp and dart each bound `Service.run`/`Service::run` high from a `service` holding an int or `Object`. Only the python, javascript, typescript, swift and objc docs describe the heuristic.
4. **dart.md §05, callback settling "Fails when the type name is a single letter … root cause unverified":** the root cause is `concrete_class`, which refuses any type whose last segment is shorter than two characters (`last.chars().count() < 2`, type_hints.rs:1358-1360), as a type-parameter guard. This is deliberate, not a bug.
5. **dart.md §05, "`is` promotion inside an `if`" (listed under Supported, flagged unverified):** not supported. In fixture `narrow/dart`, `void f(Object p) { if (p is Foo) { p.go(); } }` left the site unresolved with receiver `Object` (`candidates-in-other-files`, 2). It belongs under "Not supported".
6. **csharp.md §05, "`TOP_TYPES` … the entry only matters for `System.Object`-style spellings"; scala.md §05, "Top types … say nothing about the receiver (`TOP_TYPES`)"; dart.md §05, "Top types":** `TOP_TYPES` is read only by `concrete_class` (type_hints.rs:1363), which is used only when settling callback types for untyped closures. It does not stop a parameter typed `Any`/`Object` from being rewritten to that type: `parse_colon_param` (type_hints.rs:2009-2050) and `parse_type_first_param` never consult it. The Scala `x: Any` → `fanout-cap-exceeded (6)` result therefore comes from some other path; which one is unverified.
7. **r.md §05, "`$` receivers are untyped":** not always. When the file defines a function whose name is the receiver capitalised, Strategy 2 retypes the receiver, and the site loses its by-name binding. In fixture `heur2/r`, `f <- function(service) service$run()` with a top-level `Service <- function() 1` ended unresolved with receiver `Service` (`candidates-in-other-files`, 1), while the identical `g(zzz)` bound `run` at medium.
8. **groovy.md §05, typed closure parameters "(unverified by fixture, but no code path exists)":** now verified. In fixture `narrow/groovy`, `[1].each { Foo d -> d.go() }` fanned out to `Foo.go` and `Bar.go` at medium. In the same fixture, `Foo x = new Foo(); x.go()` also fanned out, which confirms the "Typed locals" gap.
9. **java.md §05 and csharp.md §05, return types:** both are correct that Java and C# return types are not extracted. To be precise, the misleading comment is at type_hints.rs:2650-2652 ("Java/C#/Go: return type is before the function name"), and the only branch below it (:2662-2669) reads the text *after* the closing parenthesis, which serves Go and Zig.
