## Observations

Evidence key: **[fixture]** = ran `target/release/cgg` (built 2026-10-16) on a
fixture under the scratch dir; **[code]** = file:line; **[upstream]** = framework API
knowledge not checked against the framework's own source here — treat as unverified.

### Fixture-confirmed defects or misses

1. **`swing` (java, 11216) roots by name across the whole tree.** It has `methods` and no
   `base_types`, so `match_methods` (mod.rs:996-1050) roots every Java callable named
   `drop`, `valueChanged`, `propertyChange`, `stateChanged`, `insertUpdate`, … once any file
   imports `javax.swing`/`java.awt.event`. [fixture] `Ui.java` imports `javax.swing.JFrame`;
   `store/Store.java` imports nothing and declares `drop()` and `valueChanged()`:
   `--why-live 'store.Store.drop$'` → `LIVE (root itself) [FrameworkCallback]`, and neither
   appears in `--dead-code`, while `Store.unusedThing` does. The listener interfaces
   (`ActionListener`, `MouseListener`, `DocumentListener`, …) are not listed as bases, which
   is what would gate it.
2. **`rtic` (rust, 9212) claims non-RTIC executors.** It is marker-only and matches the
   attribute's last segment, so `#[embassy_executor::task]` (Embassy) mints an
   `rtic` entry. [fixture] a file with only `use embassy_executor::Spawner;` and
   `#[embassy_executor::task] async fn blink()` → coverage `rtic (lifecycle, 1 entry)` and node
   `<framework-entry>::lifecycle::rtic::crate::blink`. (`#[init]` / `#[idle]` / `#[task]` are
   not gated on `#[rtic::app]`, per the comment at rules.rs:9208-9211.)
3. **`godot` (csharp, 10863) base list misses common engine types.** Base matching walks
   only in-tree bases (mod.rs:933-969), so an engine class absent from the list is a miss.
   [fixture] `class Hud : CanvasLayer { override _Ready() }` → `_Ready` reported
   unreferenced; `class Player : Node2D { override _Ready() }` → rooted. Absent from the
   list (all Godot 4 Node/Resource subclasses [upstream]): `CanvasLayer`, `MarginContainer`,
   `GridContainer`, `ScrollContainer`, `CenterContainer`, `CheckBox`, `OptionButton`,
   `HSlider`/`VSlider`, `SpinBox`, `Viewport`/`SubViewport`, `MeshInstance3D`, `Path2D`,
   `PathFollow2D`, `Line2D`, `Polygon2D`, `RayCast2D`/`RayCast3D`, `NavigationAgent2D/3D`,
   `GpuParticles2D/3D`, `Light2D`/`PointLight2D`, `DirectionalLight3D`, `TileMap`,
   `AnimationTree`, `HttpRequest`, `Marker2D/3D`, `VisibleOnScreenNotifier2D`.
4. **`angular` (typescript, 11316) needs `implements OnInit`.** Angular invokes `ngOnInit`
   etc. whether or not the class implements the interface [upstream], but the rule's
   `methods` are only consulted through `base_types` (mod.rs:1002: methods-only matching
   is skipped when base_types is non-empty). [fixture] `@Component` class importing
   `@angular/core` with `ngOnInit()`/`ngOnDestroy()` and no `implements` → both reported
   unreferenced; coverage lists `angular` and `angular-host` under "seen, no rules".
5. **`react` (typescript 11414 / javascript 11446) omits `render`.** A class component's
   `render()` is called by React [upstream]; it is not in `methods` and no other rule roots
   it. [fixture] `class App extends React.Component { componentDidMount(){} render(){} }`
   → `render` unreferenced, `componentDidMount` rooted (`react (lifecycle, 1 entry)`).
6. **`rails-callbacks` (ruby, 10724) omits `validate`.** `validate :check_name` registers
   a model method exactly like `before_save :normalize` [upstream]. [fixture] model with
   both → `normalize` rooted, `check_name` reported unreferenced. Other symbol-taking
   registrations missing from the verb list [upstream, unverified]: `validates_with`,
   `validates_each`, `helper_method`, `before_commit`.
7. **`actioncable` (ruby, 10789) roots private helpers as network entries.** `methods` is
   empty, so every member of a Channel/Connection subclass is "named" (mod.rs:896-897) and
   minted as a `network` entry. [fixture] `ChatChannel#secret_helper` under `private` →
   `LIVE … from <framework-entry>::network::actioncable::ChatChannel::secret_helper`. This
   overstates attack surface (Network kind); ActionCable only dispatches public channel
   actions [upstream]. All five APPS claims are `~` (detected, nothing enumerated), so no
   app exercises the enumerating path.
8. **Stale gap text: `avalonia-xaml` (11082), `maui` (10514), `wpf-winforms` (10531) say
   `.xaml`/`.axaml` "is not parsed at all".** The `xaml` rule (9724, comment
   9721-9723: "WPF / Avalonia / MAUI") reads the sibling `.xaml`/`.axaml` of a
   `*.xaml.cs`/`*.axaml.cs` code-behind (markup.rs:31-33). [fixture]
   `MainWindow.axaml` (`<Button Click="OnSave"/>`) + `MainWindow.axaml.cs` with
   `OnSave(object sender, RoutedEventArgs e)` → coverage `xaml (ui, 1 entry)` and `OnSave`
   rooted, while the same run prints `avalonia-xaml`'s "`.axaml`/`.xaml` is not parsed"
   under "seen, no rules". The gaps remain true for `Command="{Binding …}"`, `{Binding}`
   getters, handlers whose signature lacks an `…EventArgs` parameter (markup.rs:117-121),
   and markup with no same-stem code-behind.
9. **`junit-sources` has no Kotlin twin.** `member_sources_for` lists
   `("junit-sources","java")` only (rules.rs:11721), while `junit` exists for kotlin
   (7495). [fixture] identical JUnit 5 test in Java and Kotlin, `@MethodSource("words")`:
   Java `words` → `LIVE ONLY IN TESTS [TestEntry]`; Kotlin `words` → `NOT REACHED`.
