## How to read the columns

- **kind**: the `TrustKind` variant.
- **node**: `node: true` mints a `<framework-entry>` node. `false` only root-marks the target for dead-code.
- **triggers**:
  - `detect` holds import prefixes. `detect_paths` and `detect_calls` are the other detection inputs (`Detection::scan`, `crates/cgg-resolve/src/frameworks/mod.rs:264-330`).
  - `attributes`, `registrars`, `base_types`, `methods` and `observer_types` are the matchers.
  - **helper** lists matchers that sit outside the struct, in the `*_for` tables (`rules.rs:11666-11870`).
- **detection-only / enumerating**: this follows `FrameworkRule::has_matchers` (`crates/cgg-core/src/frameworks.rs:301-322`), which counts the helper tables too. `docs-check.py::check_framework_apps` (`scripts/docs-check.py:527-533`) counts only `attributes|registrars|base_types|methods`. The two definitions agree for every row in this slice.
- **benchmark apps**: taken from `APPS=(…)` in `scripts/benchmark.sh` (L135). `enumerates:` means the id is listed bare. `~` means the app lists it as "detected, enumerates nothing". APPS ids carry no language, so a claim on an id that has both a JS and a TS row (or a Java and a Kotlin row) cannot say which language's rule it exercises. `APPS_UNVERIFIED` (L476) is **empty**. "unverified (no APPS entry)" means no APPS line names the id at all.
- **gap_for text**: the `gap:` string verbatim, read by `rules::gap_for` (`rules.rs:11876`). `into_coverage` shows it only for a rule with **no** matchers (`frameworks/mod.rs:395-412`). A gap on an enumerating rule is never printed, and those rows say so.

Matching semantics that apply to every row below (all in `crates/cgg-resolve/src/frameworks/mod.rs`):

- **Name patterns** (`name_pattern_matches`, L570-584):
  - `prefix*` matches only when the character after the prefix is not lowercase, unless the prefix already ends in a non-alphanumeric character. `test*` takes `test_x` and `testX` but not `testing`.
  - `*suffix` is a plain suffix match.
  - Anything else is a case-insensitive exact match.
- **`methods` with no `base_types`** (`match_methods`, L996-1053):
  - The rule fires on **any callable of the language anywhere in the tree** once the rule is active in any file. `is_active` is tree-wide (L362).
  - Only `TrustKind::Test` rules are narrowed, to test-role files or files that carry the rule's own detection (L1013-1023).
- **`methods` with `base_types`**: the methods filter the members of classes whose base chain (depth 8) names a base type (`match_base_types`, L869-931). In python, php and ruby (`TEST_CLASS_MEMBERS_ARE_ROOTS`, `rules.rs:11806`), the members of a test class whose names do not match become test root marks with no node (L888-896).
- **Per-rule tests**: none of the ids in this slice has a dedicated test outside `rules.rs`. `grep -rln '"<id>"' crates --include=*.rs` finds only `eunit`/`py-unittest` in `deadcode/roots.rs` and `junit-sources`/`falcon`/`pytest` in `frameworks/mod.rs`. The comment above `APPS_UNVERIFIED` in `scripts/benchmark.sh` (L440-475) says the same of the table as a whole.

### A. Gap texts that are stale or contradicted by current code

None of these is printed today, because each rule has matchers (see the column note). They are still wrong in source, and they become wrong output if a matcher is ever removed.

   - **What the gap says**: "cgg … has neither a suffix matcher nor a preprocessor, so no EUnit test is enumerable."
   - **What the code does**: the rule's own `methods` are `*_test` / `*_test_`, and `name_pattern_matches` implements suffixes (`frameworks/mod.rs:580-582`).
   - **Fixture `fx/erl`**: `foo_tests:simple_test` and `foo_tests:gen_test_` both became entries ("eunit (test, 2 entries)").
2. **`common-test` (L5861)**

   - **What the code does**: the rule does exactly that. Its `methods` are `all`, `suite`, `init_per_suite`, ….
