## How the fields are used (matching semantics)

These semantics determine what each trigger means. All references are to `crates/cgg-resolve/src/frameworks/mod.rs` unless stated otherwise.

- **Detection gate** (`Detection::scan`, mod.rs:162–347). A rule turns on for a *language*, repo-wide, when at least one file of that language meets one of these conditions:
  - an import matches a `detect` prefix (segment-aware, `import_matches` mod.rs:492–509);
  - the file path matches a `detect_paths` marker (suffix on a segment boundary, `path_matches` mod.rs:518–526);
  - the file calls a `detect_calls` name.

  A rule with all three empty is "marker-only". It turns on when a callable in the file carries one of its `attributes`, its helper container attributes or markup kinds, or its visibility keywords (mod.rs:265–311). Once on, a rule runs on **every** callable of that language, not only on the files that carry the marker. `match_methods` restricts this only for `kind: Test` (mod.rs:1015–1025).
- **attributes** (shape A, `match_attributes` mod.rs:591–631). The attribute's key (`#[`/`[`/`@` stripped, arguments dropped, `deadcode/roots.rs:297`) or its last `.`/`:` segment ("verb", roots.rs:347) is compared case-insensitively against the list. The `prefix*`/`*suffix` patterns are case-sensitive (mod.rs:566–589). The first string argument becomes the route.
- **registrars** (shapes B/C/E/F, `match_registrars` mod.rs:1394–1593). Captured call references whose verb (last segment of the callee context) is in the list. Verbs in `AMBIGUOUS_VERBS` (mod.rs:546–550: get, post, put, delete, patch, head, options, add, all, use, route, match, handle, process, on, view, resource, any, list, create, update) count only with a route string or with no receiver. A module-path string resolves a whole file (shape F). A value that names a *type* expands to the rule's `methods` on that type. String handler names are decoded only when `string_targets: true` (shape E).
- **base_types** (`match_base_types` mod.rs:869–931). The match walks the declared base chain (depth 8, last segment and generics stripped, case-insensitive). With empty `methods`, **every** member of a matching class is an entry. With `methods`, only those names are entries. In python/php/ruby, other members of a `Test`-kind class become test root marks (rules.rs `TEST_CLASS_MEMBERS_ARE_ROOTS`).
- **methods without base_types** (`match_methods` mod.rs:996–1050). A name-only match against every callable of the language once the rule is active ("structural-typing escape hatch"). If the rule has `base_types`, `methods` only filters base-type matches.
- **node**: `false` means the match is only a root mark and no `<framework-entry>` node is minted (see test `bucket_d_lifecycle_rules_do_not_mint_nodes`, rules.rs tests).
- **gap** (`gap_for`, rules.rs). It is read only for rules **without** matchers (`has_matchers()` false, `crates/cgg-core/src/frameworks.rs:301`), which land in "seen, no rules" with that reason (mod.rs:395–412). A rule *with* matchers that found nothing gets the fixed reason "detected, but no entry point matched its rules" (mod.rs:421–436). No other code reads `gap` (grep of `crates/` and `scripts/` for `gap_for`/`.gap` finds only mod.rs:403).
- **Helper tables outside `RuleSpec`** (rules.rs:11627+) that give a slice rule extra matchers:
  - `container_attributes_for` (ffi-export/rust);
  - `visibility_entries_for` (solidity-public);
  - `self_module_markers_for` (worker-threads js/ts);
  - `member_sources_for` (nunit-runner, xunit-data).

  These count as matchers in `has_matchers` and are listed in the triggers column.

### Classification column

- **enumerating**: `has_matchers()` is true.
- **detection-only**: no matcher of any kind, only a `gap` string.
- **enumerating (also carries gap text)**: has matchers *and* a non-empty `gap`. As noted above, that gap text is never shown to a user (see Observations §1).

`scripts/docs-check.py:527–534` (`check_framework_apps`) uses a text approximation of the same split: a rule is detect-only when none of attributes/registrars/base_types/methods is written as `&[` and `gap` is non-empty. For every rule in this slice it agrees with `has_matchers()`. The one const-valued field, flask's `methods: HTTP_VERBS`, sits next to `&[` attributes, and the two helper-only enumerators, `solidity-public` and `xunit-data`, have an empty gap.

### Benchmark-app column

Each `APPS` row in `scripts/benchmark.sh:135+` is `name|url|frameworks`. A leading `~` means "detected on this app but expected to enumerate nothing" (benchmark.sh comment above `APPS=(`). Claims are made **per rule id, not per language**, so `express` lists the same apps for its javascript and typescript rules. `APPS_UNVERIFIED=( )` is **empty** (benchmark.sh:476–477), so "unverified" here means no `APPS` row names the id at all. All 14 such ids in this slice are detection-only, which `check_framework_apps` does not require to have an app.

## Observations

### 1. The gap text of enumerating rules is never shown

Nine rules in this slice have matchers **and** a `gap` string:

- aws-lambda-powertools (1671);
- cloudflare-workers js and ts (2060, 2100);
- deno-http js and ts (2140, 2157);
- aws-lambda-go (2465);
- azure-functions csharp and fsharp (2495, 2518);
- xunit (2577).

`gap_for` is read only for rules where `has_matchers()` is false (mod.rs:395–412). A matcher-bearing rule that finds nothing is reported with the fixed string "detected, but no entry point matched its rules" (mod.rs:421–436). Nothing else in `crates/` or `scripts/` reads `gap`. So the caveats these rules write never reach a user. Examples: "every entry reports `network`, but only `fetch` is" (cloudflare-workers), "the trigger sits on the method's FIRST PARAMETER" (azure-functions), and the event-struct caveat (aws-lambda-go).

### 2. Gap texts that contradict the current code

- **xunit (2577).** The gap begins "cgg has no entry rules for xUnit", but the rule has `attributes: &["Fact", "Theory"]`. The `fx/xunit` fixture shows `recognised xunit (test, 2 entries)` and a `<framework-entry>::test::xunit` node with `entry` edges to both methods.
- **yii (2895).** The gap says "cgg has no matcher for a method-name prefix like action*". `methods` and the base-type `named` filter both go through `matches_ci_or_pattern`, which supports `prefix*` (mod.rs:566–589, 896–897, 1023). An `action*` pattern is bounded: the next character must not be lowercase, so it accepts `actionIndex` and refuses `actions`. A rule with `base_types: ["Controller", …]`, `methods: ["action*"]` is therefore expressible. Whether it would be precise enough is unverified.
- **nunit (2594).** The gap says "[ValueSource] on a parameter" is not covered, but `member_sources_for("nunit-runner","csharp")` lists `ValueSource`. The gap also says parameter attributes are not recorded, which would make that helper entry dead. Which half is true is unverified.

### 3. Shared detect prefixes produce spurious "seen, no rules" lines

- **aspnet-minimal.** It detects on `"Microsoft.AspNetCore"` (1178), as aspnet-mvc does (1152). In `fx/aspnet`, a plain MVC controller reports `aspnet-minimal — found in 1 file(s), entries NOT enumerated / detected, but no entry point matched its rules`.
- **xunit-data.** It detects on `"Xunit"` (2642), as xunit does. In `fx/xunit`, any xUnit project without `[MemberData]`/`[ClassData]` reports `xunit-data` as an un-enumerated gap.

Both lines read as coverage gaps when there is nothing to enumerate.

### 4. Name-only (`methods` without `base_types`) rules fire on every callable of the language once any file triggers detection

`match_methods` (mod.rs:996–1050) does not require the matched callable's own file to import the framework, except for `kind: Test`.

- **net-http (885).** In `fx/gohttp`, `a/a.go` imports `net/http`, while `b/b.go` imports nothing and declares `func (t T) ServeHTTP() {}` (no parameters). The result was `<framework-entry>::network::net-http::b.T.ServeHTTP`, a **network** entry node.
- **otp (2946).** In `fx/otp`, `a.ex` has `use GenServer`. `b.ex` is a plain module, yet its `init` and `terminate` were root-marked (`otp (lifecycle, 3 entries)`, 3 root-marked).
- **Same exposure, unverified by fixture:**
  - **otp-application (2973):** any Elixir `start`.
  - **cloudflare-workers (2060/2100):** any JS/TS method named `fetch`, `scheduled`, `queue`, `email`, `trace` or `tail`, all minted as `network` nodes.
  - **deno-http (2140/2157):** any `fetch`. Its detect prefix `"https://deno.land"` matches every Deno URL import, not only the HTTP server.

### 5. Base-type rules with no `methods` make every member an entry, including private helpers

`named = rule.methods.is_empty() || …` (mod.rs:896–897). In `fx/aspnet`, `private int helperNotAnAction()` on a `Controller` subclass got its own `<framework-entry>::network::aspnet-mvc::HomeController.helperNotAnAction` node. The same applies to codeigniter (1132, `BaseController`/`Controller`, no methods), unverified by fixture.

### 6. Trigger sets that look incomplete (each confirmed absent from rules.rs by grep)

- **spring/kotlin (769)** has 6 attributes. spring/java (601) has 10; the Kotlin rule lacks `MessageMapping`, `ExceptionHandler`, `InitBinder` and `ModelAttribute`. In `fx/spring`, `@ExceptionHandler fun kHandler()` in `K.kt` got no entry, while the identical Java method `J.jHandler` did (`network::spring::J.jHandler`).
- **wordpress (1101).** `register_activation_hook` is a registrar, but its canonical form `register_activation_hook(__FILE__, 'my_activate')` produced **no** entry in `fx/wp`. Only `add_action('init', 'my_init')` bound. With a string-literal first argument (`fx/wp2`: `register_activation_hook('plugin.php', 'my_activate')`) it binds. The `__FILE__` idiom is the one WordPress documents; the cause is unverified, likely that route capture needs a literal first argument. `register_deactivation_hook` and `register_uninstall_hook` are not registrars at all: grep of rules.rs finds no `register_deactivation_hook`, and `my_deactivate` got no entry.
- **fastapi (94)** has no `on_event`. In `fx/fastapi`, `@app.on_event("startup") def boot()` got no entry while `@app.get("/x")` did. `lifespan=` handlers are also absent (grep: no `"lifespan"`).
- **flask (124).** Blueprint-level hooks `before_app_request`, `app_errorhandler` and `teardown_appcontext` are absent from rules.rs. That these are real Flask decorators is from upstream knowledge, unverified here. The same goes for `before_first_request` and `context_processor`.
- **nestjs (446)** has no `OnEvent` (@nestjs/event-emitter), `GrpcMethod`, `Process`/`Processor` (@nestjs/bull) or GraphQL `Query`/`Mutation`/`ResolveField`. None appears anywhere in rules.rs, nor in `crates/cgg-resolve` or the cgg-core dead-code tables (grep for `OnEvent`, `GrpcMethod`). `"Process"` occurs only at rules.rs:6826 and 10431, in other rules. NestJS microservice `MessagePattern`/`EventPattern` are covered.
- **axum (1275)** has no `fallback` registrar. **actix-web (1301)** and **rocket (1329)** have no `launch` attribute: grep for `"fallback"` and `"launch"` finds nothing. Rocket's `#[launch]` fn is its `main`; an unverified upstream fact.
- **chi (856)** has no `MethodFunc`, `NotFound`, `MethodNotAllowed`, `Mount`, `Connect` or `Trace`. **gin (796)** has no `NoRoute`/`NoMethod`; `NoRoute` exists only at rules.rs:8975, the `hertz` rule. **echo (816)** has no `CONNECT`/`TRACE`/`Match`. **fiber (836)** has no `Connect`/`Trace`. These verbs are in the shared `HTTP_VERBS` (rules.rs:70–72), but the Go rules use their own lists. That those APIs exist upstream is unverified here.
- **symfony (1070)** has no `AsEventListener` attribute and no `EventSubscriberInterface::getSubscribedEvents` handling (grep: none). Symfony Messenger has a separate rule at 10558 (later part).
- **sinatra (972).** Its registrars only match call arguments. The benchmark.sh comment above `APPS=(` says the Sinatra `get "/x" do … end` block form is missed, which is why `~sinatra`-style markers exist. `before`/`after`/`not_found`/`error` filters are not listed.
- **rails (933).** `methods` lists only the seven REST actions. In `fx/rails`, `PhotosController#publish` got no entry while `#index` did. Custom actions are reachable only through `config/routes.rb` string targets (`string_targets: true`), which needs the routes file present.
- **laravel (1035).** `base_types` `Controller`/`Command`/`Job` with the methods listed. Listener `handle`, middleware `handle` and `Mailable::build` are not covered here; a later `laravel-events`/`laravel-lifecycle` rule (10587/10665) may cover some, unverified in this part.
- **Detection blind spots stated by the rules themselves:**
  - **padrino (2819):** `Bundler.require` means no `require "padrino"`.
  - **rake (2844):** a bare `Rakefile` is skipped as unknown-extension, and `.rake` files carry no `require`.
  - **sidekiq (1006):** relies on `detect_paths` `app/workers/`, `app/jobs/`.
- **grpc-java (2329) and grpc-dotnet (2560)** are detection-only because generated bases are invisible. grpc-java's gap points out that `base_type_matches` (mod.rs:971–994) uses exact `contains_ci`, not `matches_ci_or_pattern`, so a `*ImplBase` suffix pattern is **not** supported for `base_types` even though it is for `attributes`/`methods`.

### 7. Sibling-language asymmetries (same framework family, one language covered)

The language sets below come from the full-table id×language listing, i.e. every `RuleSpec` id/language pair in rules.rs.

- **JVM, Java-only (no Kotlin/Groovy/Scala rule anywhere in rules.rs):**
  - `spring-jobs` (629). Confirmed in `fx/spring`: Kotlin `@Scheduled fun kTick()` got no entry, while Java `J.jTick` got `schedule::spring-jobs`.
  - `spring-messaging` (646).
  - `jakarta-rs` (679).
  - `micronaut` (700). Micronaut is commonly written in Kotlin and Groovy.
  - `akka` (726). Scala has `akka-scala`/`akka-typed`; Kotlin has none.
  - `java-concurrent` (750). Kotlin has only `kotlinx-coroutines`.
  - `servlet` (2231).
  - `vertx`, `dropwizard`, `struts`, `grpc-java` (detection-only).

  By contrast `spring-batch`, `spring-integration`, `jpa-lifecycle`, `junit`, `dagger`, `guice` and `eventbus` do have Kotlin rules (kotlin list: 9901, 10017, 10059, 7495, 9556, 9579, 9602).
- **TypeScript-only:** `nestjs` (446), `nestjs-schedule` (476) and `trpc` (2174) have no javascript rule. NestJS-in-JS via Babel is uncommon; flagged for completeness.
- **.NET, C#-only:**
  - `aspnet-mvc`, `aspnet-minimal`, `dotnet-hosting`, `quartz`, `masstransit`, `wcf`, `grpc-dotnet`, `xunit`, `xunit-data`, `nunit`, `nunit-runner`, `dotnet-serialization` have no fsharp rule.
  - `azure-functions` *does* have an fsharp twin (2518, with the source comment "F# is the same .NET runtime as C# and carries the same attributes"). That shows F# attributes are recorded, so the omissions are not technical.
  - F# has `fsharp-nunit` (6182) and `expecto` but no xUnit (`[<Fact>]`) rule.
- **Python only:** `aws-lambda-powertools` (1671). Powertools also ships for TypeScript, Java and .NET (upstream knowledge, unverified); no such rule exists for those languages in rules.rs.
- **gRPC servers.** Java, Go, C# and Rust (tonic) all have detection-only rules. Python (`grpcio`) and JS/TS have **no** gRPC rule at all (no python/javascript/typescript id containing `grpc` in the listing).
- **FFI export.**
  - `ffi-export` (rust, 1444) has siblings `dotnet-ffi-export` (csharp, 9378) and `zig-export` (6612).
  - C and C++ have no export-attribute rule (`__declspec(dllexport)`, `__attribute__((visibility("default")))`). The c/cpp ids are cuda, c-runtime, c-callbacks, aws-lambda, gtest, cpp-test-macros, cpp-runtime and cpp-callbacks; whether `c-runtime`/`cpp-runtime` cover exports is unverified in this part.
- **CUDA** is covered for both c (1398) and cpp (1377). **Elixir OTP** (`otp`, `otp-application`) has its Erlang siblings `erlang-gen-server` (5764), `erlang-otp-lifecycle` (5794) and `erlang-application` (5820).
- **CLI families.** click (python) enumerates via attributes. cobra/urfave-cli (go), clap (rust) and rake (ruby) are detection-only because their command bodies are struct fields or match arms or blocks (per their gap texts).
- **Desktop IPC.** electron (js/ts) enumerates IPC registrars and tauri (rust) enumerates `#[command]`. The JS side of Tauri (`invoke(...)`) has no rule.
